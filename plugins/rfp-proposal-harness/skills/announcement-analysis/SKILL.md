# 공고문 수집·분석 스킬

R&D 공고문을 분석해 연구계획서 작성의 출발점을 만든다. 목표는 **RFP 특정**과 **기초자료 확보**다.

## 워크플로우

### 1. 입력 판별
- URL/공고 제목 → `WebFetch`로 본문 수집, 첨부파일 링크 확인.
- 로컬 파일 → `Read`로 직접 읽기. PDF는 `pages` 지정, HWPX는 압축 해제 후 XML 텍스트 추출(`unzip -p file.hwpx 'Contents/*.xml'`).
- 국내 공고는 `NaverSearch-search_webkr`/`search_news`로 배경 정보 보완.

### 2. 공고 개요 정리
사업명·공고기관·지원규모·기간·신청자격·평가방식을 표로 정리한다. 근거 URL을 반드시 남긴다.

### 3. RFP 특정 (핵심)
- 공고에 여러 RFP가 있으면 각 RFP를 (RFP명 · 목표 · 지원규모 · 기간 · 핵심 요구)로 표에 나열.
- **임의로 고르지 말고** 사용자에게 목표 RFP 선택을 요청한다. → 이때 STATUS를 `NEEDS_USER_INPUT`으로.
- RFP가 하나면 그대로 특정. RFP가 아예 없으면 사용자에게 과제 주제를 입력받는다.

### 4. 기회보고서(기획보고서) 분석
있으면 배경·목표·핵심이슈를 요약하고, 후속 조사가 쓸 **키워드 후보**를 `#키워드` 태그로 남긴다.

## 출력 (파일 기반)
`_workspace/00_announcement.md`, `_workspace/00_rfp_selected.md`에 기록. 각 파일 첫 줄:
```
## STATUS: OK | NEEDS_USER_INPUT
```

**왜 파일로 남기나:** 후속 조사 에이전트들이 이 파일을 공통 입력으로 읽고, 재실행 시 감사 추적이 되기 때문.

## 주의
- 접근 실패한 첨부는 "미확보"로 표시하고 진행 — 한 파일 때문에 전체를 멈추지 않는다.
- 공고 요구사항(평가항목)은 뒤에서 평가위원이 그대로 대조하므로 **원문 표현 그대로** 옮긴다.
