# 연구과제 그림 작성 스킬

연구계획서에 들어갈 그림을 텍스트 기반으로 설계·생성한다.

## 워크플로우

### 1. 필요한 그림 도출
`01_template_rules.md`(목차)와 조사 결과에서 그림이 필요한 위치를 식별한다. 대표 유형:
- 연구 개념도 (무엇을 왜)
- 시스템/기술 구성도 (어떻게)
- 연구추진 체계·일정도 (누가 언제)
- 기대효과 다이어그램

### 2. 다이어그램 생성 (텍스트 우선)
- 구조/흐름/체계 → **Mermaid**(`.mmd`) 또는 SVG로 작성. 편집·버전관리가 쉬움.
- 스타일 일관성(색상·글꼴·라벨)은 `dataviz` 스킬 원칙을 따른다.
- 이미지가 필요하면 Mermaid/SVG → PNG 렌더. 렌더 도구가 없으면 소스 + 설명까지만 산출(STATUS: PARTIAL).

### 3. 캡션·배치 정보
각 그림에 (그림번호 · 제목 · 삽입 위치 · 한 줄 설명)을 붙인다. `hwpx-writer`가 이 정보로 본문에 배치한다.

## 출력
`_workspace/20_figures/` 하위에 그림 파일 + `20_figures/index.md`(그림 목록·캡션·삽입위치).
index.md 첫 줄: `## STATUS: OK | PARTIAL`

## 원칙
- 사람 손으로 보정해야 하는 그림은 index.md에 "수작업 필요"로 태깅한다(그림 담당자에게 넘길 목록).
- 내용 정보가 부족하면 지어내지 말고 조사 산출물을 더 요청한다.

## ★ 규율 F — 매체 동기화 (그림은 3자가 한 몸이다)
본문 문자열을 바꾸면 **본문 · 그림(SVG/PNG) · 생성기 원본(`gen_fig.py`)** 3자를 **동시에** 고친다.
- 변경 시 `grep -l '<변경 전 문자열>' 20_figures/*.svg 20_figures/_src/*.py 20_figures/index.md` 실행 의무.
- 그림 수정은 **SVG → PNG 재렌더 → HWPX 재빌드까지가 1건**이다. 완료 판정은 산출물의
  `BinData/image*.png` **해시 변경 확인**으로 한다(판 간 비교 전용 — 원본 PNG와는 재인코딩으로 해시가 다르다).
- **`index.md`·생성기 헤더에 판번호를 하드코딩하지 말 것.** 「현행 `30_proposal.md` 기준」으로 표기한다.
  > 실측: `index.md`에 `v4`를 박아둔 탓에 이후 모든 판에서 stale이 됐고, 정리 직후 다시 1판 stale이 됐다.

> 실측 사고: SVG만 고치고 `gen_fig.py`를 방치해 **재렌더 시 이미 고쳤다고 보고한 오류가 되살아났다.**
> 더 위험한 사례 — 존재하지 않는 절 `§1-4`를 **존재하지만 무관한** `§1-1`로 바꿔 `grep`을 통과시키고
> 의미 오류를 존치시켰다. 위원장이 *"검사를 통과하도록 고치는 것과 옳게 고치는 것이 갈라진 첫 사례"*로 판정했다.

## ★ 그림 가독성 게이트
**실인쇄 글자 크기 = SVG font-size ÷ viewBox 폭 × 표시폭.** viewBox 1000 · 표시폭 80%(120mm)에서
**18u = 6.1pt**다. 폰트만 키우면 가로로 넘치므로 **PNG 육안 검수가 필수**이고, 생성기에 최소 font-size를
상수로 강제해 둘 것.
