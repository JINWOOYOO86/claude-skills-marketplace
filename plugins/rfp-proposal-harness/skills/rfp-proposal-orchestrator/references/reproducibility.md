# 재현성 규율 R0~R8 — 과제명만 주어져도 두 실행이 같은 결론에 닿게 한다

> **문제**: 같은 과제명으로 하네스를 두 번 돌리면 조사원이 매번 다른 자료를 찾고, 다른 대표값을 고르고,
> 다른 정량목표를 세운다. 문서 형식은 게이트가 잡지만 **내용의 흔들림은 아무도 안 잡는다.**
>
> **규율의 요지**: 자유도를 없애는 게 아니라 **자유도를 한곳에 모은다.** 해석은 R0 에서 한 번만 하고,
> 그 뒤 단계는 앞 단계의 산출물만 본다. 수치는 대장에만 존재하고 본문은 대장을 인용만 한다.

---

## R0. 입력 정규화 — 과제명 해석은 **한 번만**, 한 파일에서

`10_project_title.md` 를 **유일한 해석 산출물**로 삼는다. 이후 어떤 단계도 과제명을 다시 해석하지 않는다.
고정 스키마(항목을 빼거나 순서를 바꾸지 않는다):

| 항목 | 내용 |
|---|---|
| 과제 슬러그 | 워크스페이스 폴더명이 되는 소문자 영숫자 키 |
| 대상(무엇을) | 개발 대상 물질·시스템·기술을 명사구로 |
| 범위 밖 | 인접하지만 다루지 않는 것 — **이걸 안 적으면 실행마다 범위가 달라진다** |
| 개발내용 축 ①~⑤ | 과제명에서 도출한 기술 축. RFP 가 있으면 원문 축을 그대로 |
| 키워드 세트 | 국문·영문 각 5~8개. **R1 검색어의 재료** |
| 성공 판정 기준 | 「무엇이 되면 성공인가」 1~3줄 |

### R0-2. 과제 파라미터도 **여기서 한 번** 정한다

연구기간·단계 구성·TRL(착수/종료)·총 연구개발비·주관기관 유형은 **조사 결과가 아니라 과제 설계값**이다.
R0 에서 정해 대장의 `과제설계` 축(`PRJ_*` 6 key)에 적고, 이후 단계는 그 값만 인용한다.

> **실측(2026-08-15)**: 이 값을 고정하지 않았더니 같은 과제명 3회 실행의 TRL 이
> `3→6` / `협약 시 확정→7` / `4→7` 로 갈렸다. 문장 유사도는 0.81 이었는데
> **결론 일치도는 0.44** 였다 — 표현은 같고 결론이 다른 문서였다.

RFP 가 있으면 원문 값을, 없으면 유사 과제 근거로 정하고, 근거가 없으면 `미확인`(본문 「협약 시 확정」).

## R1. 검색어 고정 — 실행마다 같은 질문을 던진다

축별 **표준 질의 템플릿**을 쓴다. `{키워드}` 는 R0 의 키워드 세트에서만 채운다.

| 축 | 표준 질의(순서 고정) |
|---|---|
| 기술동향 | `{대상} 기술 동향` / `{대상} 최고 기술 보유 기업` / `{대상} 국내 기술 수준` / `{영문키워드} state of the art` |
| 시장 | `{대상} 시장 규모 {연도}` / `{영문키워드} market size forecast` / `{대상} 국내 시장` / `{대상} 주요 기업 점유율` |
| 정책 | `{대상} 규제 시행` / `{대상} 전환 일정 공고` / `{영문키워드} regulation phase down` / `{대상} 국가계획` |
| 특허 | `{대상} 특허 동향` / `{영문키워드} patent expiry` / `{CPC/IPC} 분류` / `{주요기업} 원천특허` |

- 질의 수 상한을 **축당 12회**로 둔다. 상한이 없으면 실행마다 탐색 깊이가 달라져 결과가 갈린다.
- 실제로 던진 질의를 산출물 말미에 **원문 그대로** 남긴다(다음 실행이 같은 질의를 재현할 수 있게).

## R2. 출처 계층 — 상위 계층이 있으면 하위를 대표값으로 쓰지 않는다

```
① 법령·고시·공고 원문        ② 국가통계·법정 실적공고
③ 국제기구(IEA·UNEP 등)      ④ 정부출연연·전문기관 보고서
⑤ 시장조사기관 공개요약      ⑥ 언론·블로그(보조 근거로만)
```
- 같은 사실에 ①②가 있으면 ⑤⑥의 수치를 본문 대표값으로 올리지 않는다.
- 계층을 산출물에 **명시**한다(출처 옆에 `[출처계층 ②]`). 이것이 실행 간 값 차이를 줄이는 가장 큰 지렛대다.

## R3. 확정 수치 대장 — 수치는 **대장에만** 산다

조사 산출물마다 마지막에 `## 확정 수치 대장` 을 둔다.

| 지표명 | 값 | 단위 | 기준연도 | 출처(계층) | 확신도 |
|---|---|---|---|---|---|

- **본문·계획서는 대장에 없는 수치를 쓰지 않는다.** 새 수치가 필요하면 대장에 먼저 추가한다.
- 확신도 `상`은 ①②계층 + 원문 확인, `중`은 ③④, `하`는 ⑤⑥·추정.
- 계획서 작성 단계는 **확신도 `하` 값을 단독 근거로 쓰지 않는다**(반드시 「추정치」 표기).

## R4. 편차 처리 — 대표값을 임의로 고르지 않는다

기관마다 값이 다르면 다음 순서로만 정한다.

1. **대역을 그대로 적는다** — `99.5~281.8억 달러(FBI/IMARC/Mordor, 2025)`
2. 본문 인용이 필요하면 **가장 최신·가장 높은 계층** 출처의 값을 쓰고 그 사실을 적는다
3. 중앙값·평균 등 **가공값은 만들지 않는다**(만들면 실행마다 달라진다)

## R5. 정량목표(KPI) 도출 — RFP 가 없으면 표준 6항목 틀

공고 RFP 가 있으면 **원문 지표를 그대로** 쓴다. 없으면 아래 틀에서 도출한다(항목을 늘리지 않는다).

| # | 지표 축 | 목표치 도출 근거 |
|---|---|---|
| 1 | 핵심 산출물 **개발 수**(모델·장치·물질 등) | R0 개발내용 축 개수 |
| 2 | **정확도·성능 지표** | 대장의 최고수준 값 대비 |
| 3 | **생산·처리량** | 실증 규모에서 역산 |
| 4 | **대비 성능비(%)** | 기존 대조군 대비 실용 하한 |
| 5 | **절차·표준화 산출물** | 1건(절차서·프로토콜) |
| 6 | **실증 규모**(시간·대수) | 요구 수준이 없으면 대장의 유사과제 값 |

- 가중치는 합 100%, **실증·성능(4·6)에 35% 이상**을 배분한다.
- 지표마다 **단위·기준값·목표치·평가방법·평가환경 5요소**를 붙인다(양식 요구).

## R6. 문서 규격 — 게이트가 고정한다

`gate_form.py`(양식·개조식·글자크기·굵기) + `gate_pages.py`(총 분량·장별 배분) + `gate_hwpx.py`(구조).
서식·목차·분량은 **실행 간 흔들릴 수 없다** — 흔들리면 게이트가 FAIL 한다.

## R7. 라운드 상한 — **최대 3회**

라운드당 위원 6명이 붙어 비용이 라운드 수에 비례한다. R1 채점 → R2 개정 → **R3 검증 전용**으로 끝낸다.
3회 안에 목표에 못 닿으면 무리하게 통과시키지 말고 **잔여 리스크로 보고**한다.

## R9. ★ 근거팩 동결 — 재현이 목적이면 조사를 매번 새로 하지 않는다

**실측(2026-08-15, 같은 과제명 3회 완전 독립 실행)**: 문서 구조는 1.00, 골격(□ 리드 37 · ㅇ 슬롯 76)은
**전 실행 100% 일치**, 게이트는 3건 모두 전항 PASS 였는데도 **계획서 서술 유사도는 0.58~0.63** 에 머물렀다.
원인은 작성 단계가 아니라 **조사 단계**다 — 대장 값 일치가 0.63 이었고, 문자의 85%가 그 값을 서술하는 문장이다.

> **웹 검색은 비결정적이다.** 같은 질의라도 결과·요약이 실행마다 달라지고, 검색 예산이 소진되면
> 도구 자체가 바뀐다(실측: 3회 실행 모두 세션 검색 한도 200/200 소진 → 네이버·직접 fetch 로 대체).
> 이 층을 그대로 두면 어떤 규율을 더해도 유사도 상한이 0.6 대에 걸린다.

**규율**: 재현이 목적이면 **조사를 한 번만 하고 그 결과를 동결**한다.

1. 첫 실행의 조사 산출물 5종(+확정 수치 대장)을 `evidence_pack/` 으로 복사하고 **SHA-256 을 기록**한다.
2. 이후 실행은 **팩만 입력으로 받고 웹 검색을 하지 않는다.** 팩에 없는 수치는 「협약 시 확정」.
3. 팩 갱신은 **명시적 사건**(규제 개정·분기 정기 갱신)일 때만. 갱신 시 이전 팩과의 **값 diff 를 남긴다**.
4. 팩을 쓴 계획서에는 팩 해시를 매니페스트에 적는다 — 어떤 근거로 쓴 문서인지 나중에 증명할 수 있어야 한다.

**언제 동결하지 않나**: 최신 근거가 목적일 때(공고 대응·실제 제출용). 그때는 재현성이 아니라 **정확성**이 목표이므로
매 실행 새로 조사하고, 유사도 목표를 0.6 대로 낮춰 잡는다. **둘을 동시에 요구하지 않는다.**

## R8. 재현성 측정 — 느낌이 아니라 수치로

```bash
python3 $CLAUDE_PLUGIN_ROOT/skills/proposal-evaluation-panel/scripts/compare_runs.py \
    --a _workspace/run_A --b _workspace/run_B --out 재현성_보고서.md --json 재현성.json
```

| 층위 | 무엇을 보나 | 목표 |
|---|---|---|
| **L6 결론 일치** | **표의 결론**(연구기간·TRL·최종목표·KPI 목표치·연차 목표·일정) | **≥ 0.90 ← 주지표** |
| L1 산출 구성 | 같은 파일이 나왔는가 | 1.00 |
| L2 문서 구조 | 장·절 집합 | **1.00**(양식 고정이므로 미달이면 규격 위반) |
| L3-a 지표 집합 | 대장 지표명 | ≥ 0.60 |
| L3-b **값 일치** | 공통 지표의 값 | **≥ 0.80** ← 가장 중요 |
| L4 근거 개체 | 특허번호·기관·기준값 | ≥ 0.40 (웹 검색이 비결정적이라 1.00 은 불가능) |
| L5 서술 유사도 | 3-gram 코사인 | **0.65~0.75 면 충분**(참고값). 더 올리려 문장을 조이면 분량·충실도가 깎인다 |

- **L3-b 가 목표 미달이면 R2·R4 를 손본다**(출처 계층 미명시·대표값 임의 선택이 주원인).
- L4 가 낮으면 R1(검색어 고정)이 느슨한 것이다.
- 보고서의 「값이 갈린 지표」 표가 **다음 개선 작업 목록**이다.

## ★ 경진대회 모드 — 무엇을 최적화할 것인가

산출물이 **자동채점 + 시연**으로 평가되는 경우(KIMM AI 경진대회 주제1 등)의 설정이다.

| 항목 | 값 | 이유 |
|---|---|---|
| 주지표 | **L6 결론 일치 ≥ 0.90** | 심사자가 보는 것은 표현이 아니라 **결론**이다 |
| 참고지표 | L5 서술 0.65~0.75 | 더 올리려면 문장을 조여야 하고, 그러면 분량이 깎인다 |
| 분량 | **10p 내외 유지** | 자동채점 대상이 문서 충실도다. 6p 짜리는 게이트를 통과해도 손해다 |
| 슬롯 | 115자·근거 1개 이상 | 70자 상한은 유사도는 올렸지만 문서를 6~8p 로 눌렀다 |
| 근거팩 | **동결(R9)** | 시연에서 「같은 팩 → 같은 결론」이 가장 강한 장면이다 |
| 라운드 | 최대 3회 | 비용이 라운드 수에 비례한다 |

**시연 시나리오**: ① 과제명 한 줄 입력 → ② 근거팩 동결본 표시(해시) → ③ 두 번 실행 →
④ `compare_runs.py --runs` 로 **L6·구조·게이트 3종을 한 화면에** 보여준다.
「형식은 게이트가, 결론은 규율이 보장한다」가 메시지다.
