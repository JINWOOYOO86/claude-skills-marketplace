# R&D 연구계획서 자동 작성 오케스트레이터

15개 전문 에이전트를 **하이브리드 파이프라인**으로 조율해 연구계획서를 완성한다.
데이터는 `_workspace/` 파일 기반으로 전달한다(감사 추적·부분 재실행 지원).

> **실행 모드:** 하이브리드 — 순차 파이프라인 안에서 조사 단계만 팬아웃(병렬 서브에이전트).
> 모든 `Agent` 호출은 `model: "opus"`. 에이전트 정의는 `.claude/agents/`, 각 스킬은 `.claude/skills/`.

## 파이프라인 개요
```
Phase 0.5 공고탐색(rfp-scout@jinwoo-skills)                                      [선택: 공고 미정일 때만·별도 플러그인]
Phase 1  공고문분석(announcement-analyst) → 템플릿추출(template-extractor)      [순차]
Phase 2  기술동향(tech-trend-researcher)                                        [먼저: 과제명·키워드 확정]
         → 시장(market-researcher) ∥ 정책(policy-researcher)                    [병렬 팬아웃]
         → 특허(patent-researcher)                                             [시장 후: 기업목록 사용]
Phase 3  그림(figure-designer) ∥ 준비 → HWPX 조립(hwpx-writer)                   [작성]
Phase 4  평가위원단 6인 병렬채점 → 위원장 종합 → REVISE면 개정 (전원 95점까지)   [검수·고도화]
```

## Phase 0: 컨텍스트 확인 (항상 먼저)
1. 프로젝트 루트에 `_workspace/`가 있는지 확인한다.
   - **없음** → 초기 실행. `_workspace/` 생성.
   - **있음 + 사용자가 부분 수정 요청**("특허조사만 다시" 등) → **부분 재실행**: 해당 에이전트만 재호출, 하류 파일 갱신 필요 여부 판단.
   - **있음 + 새 공고/새 주제 입력** → **새 실행**: 기존 `_workspace/`를 `_workspace_prev/`로 이동 후 초기 실행.
2. 사용자에게 목표(공고문/RFP/주제)와 실행 범위를 확인한다.
3. **공고 지정 여부로 진입 지점을 가른다.**
   - 공고문·URL·주제가 이미 있음 → **Phase 1로 직행**(탐색 불필요).
   - "낼 만한 공고 있나", "이번 분기 공고 훑어줘"처럼 대상이 미정 → **Phase 0.5 실행**.
   - "공고 탐색만" 요청이면 Phase 0.5만 수행하고 종료한다(계획서 작성으로 자동 진행 금지).

## Phase 0.5: 공고 탐색 (선택)
**같은 마켓플레이스의 별도 플러그인 `rfp-scout@jinwoo-skills` 가 담당한다**(이 하네스에 포함돼 있지 않다).
설치돼 있으면 `Agent(subagent_type=rfp-scout, model=opus)` 실행 → `00_scout_profile.md`, `00_rfp_candidates.md`.
미설치면 사용자에게 `/plugin install rfp-scout@jinwoo-skills` 를 안내하고, 그 사이 공고문·URL을 직접 받아 Phase 1로 진행한다.
- STATUS는 정상 완료 시에도 `NEEDS_USER_INPUT`이다(후보 목록 + 선택 대기). **사용자가 1건을 고를 때까지 Phase 1로 넘어가지 않는다.**
- `PARTIAL`(일부 포털 실패)이면 확보 범위를 사용자에게 알리고, 진행할지 수동 보완할지 확인한다.
- 선택된 후보의 **원문URL·첨부 목록을 그대로 `announcement-analyst`에 전달**한다. 같은 공고를 다시 찾게 하지 않는다.
- 후보 0건이면 프로파일이 좁은 것이므로 키워드 확장 또는 탐색 범위(부처·기간) 확대를 제안하고 멈춘다.

## Phase 1: 자료조사·분석 (순차)
1. `Agent(subagent_type=announcement-analyst, model=opus)` 실행 → `00_announcement.md`, `00_rfp_selected.md`.
   - STATUS가 `NEEDS_USER_INPUT`이면 **사용자에게 RFP 선택/주제 입력을 받은 뒤** 재호출. 임의 진행 금지.
2. `Agent(subagent_type=template-extractor, model=opus)` 실행 → `01_template_rules.md`.
   - 양식 우선순위는 ①사용자 지정 → ②공고 첨부 → ③**하네스 동봉 기본 양식**. **서식이 없어도 멈추지 않는다.**
   - 기본 양식으로 폴백하면 `01_template_rules.md` 에 `양식출처: 기본양식(폴백)` 이 찍힌다. 이 경우 사용자에게 알리고, 실제 제출용이면 공고 지정 서식을 요청한다.

## Phase 2: 조사 (팬아웃)
1. **먼저** `tech-trend-researcher` 실행 → `10_project_title.md`(과제명·키워드), `11_tech_trend.md`.
   - 과제명은 파급이 크므로, 필요하면 확정 과제명을 사용자에게 1회 확인받는다.
2. `10_project_title.md` 완료 후 **병렬 실행**(`run_in_background: true`):
   - `market-researcher` → `12_market.md`
   - `policy-researcher` → `13_policy.md`
3. `market-researcher` 완료 후 `patent-researcher` 실행(기업 목록 사용) → `14_patent.md`.
   - 시장조사가 지연되면 특허는 키워드만으로 시작하되 기업 축 생략을 표시.

## Phase 3: 작성
1. `figure-designer` 실행(조사 결과 기반) → `20_figures/`.
2. `hwpx-writer` 실행 → `30_proposal.hwpx`/`30_proposal.md` + `30_proposal_manifest.md`.
   - HWPX 조립은 `hwpx-writer`가 **kordoc**(`npx`, 설치 불필요)으로 처리한다. Node.js 18+ 프리플라이트가 실패하면 **조용히 md 폴백하지 말고 중단·보고**.

## Phase 4: 검수·고도화 (평가위원단 95점 게이트 루프)
`proposal-evaluation-panel` 스킬에 위임한다. 6인 위원단(위원장·기술성·실현가능성·사업화·근거정합성·형식규정)이
계획서를 병렬 채점하고, **전원 95점 이상**이 될 때까지 `hwpx-writer` 개정 ↔ 재평가를 반복한다(최대 4회).
- 위원 결과: `_workspace/41~45_review_*.md`, 위원장 종합: `49_panel_verdict.md`, 개정이력: `48_revision_log.md`.
- 근거정합성(evidence) 위원이 REVISE면 다른 점수와 무관하게 통과 불가(허위·무근거 방지 게이트).
- **R1 종료 직후 축별 산술 천장을 계산해 게이트 도달 가능성을 점검**한다(panel 스킬 Phase 0.5).
  천장 < 목표인 축이 있으면 **즉시 사용자에게 상신**하고 종료 조건을 조정한다 — 위원장 직권으로 바꾸지 않는다.
- 4회 후에도 미달이거나 최저점이 정체(+1 미만)면 "잔여 리스크" + 근본 보완(추가 조사·목표 재설정)을 제안하고 종료.
- PASS면 최종 계획서 경로 + 6축 점수표 + 수렴곡선을 사용자에게 보고.
- **개정 라운드 뒤에는 검증 전용 라운드**(신규 서술 금지, 회귀·매체 정합·필수기재만 확인)를 배치한다.

## ★ 재현·연습 과제 선언
실제 컨소시엄·기업 실적·확약서가 없는 **재현·연습 과제**는 Phase 0에서 **「재현 모드」를 선언**하고,
그로 인한 감점(기관 실명·실적 정량치·확약서·양산 캐파·CAPEX/BEP)을 축별로 사전 고지한다.
위원단은 이를 매 라운드 재발견하지 않고 **상수로 계상**한다. 실측상 이 고지가 없으면
약 −5.0점 규모의 항목이 라운드마다 재지적되며 지시·논의를 소모한다.

## 데이터 전달 프로토콜
- **파일 기반**: 모든 중간 산출물은 `_workspace/{순번}_{내용}.md`. 최종물만 사용자 지정 경로로 복사, 중간물은 보존(감사·부분 재실행).
- 각 산출 파일 첫 줄의 `## STATUS:` 라인으로 다음 단계 진행 여부를 판단한다.

## 에러 핸들링
- 에이전트 실패 시 **1회 재시도**. 재실패하면 해당 산출 없이 진행하되 최종 보고에 **누락 명시**.
- 상충 데이터(시장 수치 등)는 삭제하지 않고 **출처 병기**.
- 상류 파일 부재로 하류가 막히면, 사용자에게 어떤 단계가 필요한지 알리고 멈춘다(빈손 진행 금지).

## 팀 모드 옵션 (대안)
실시간 조율이 필요하면 Phase 2 조사 단계를 에이전트 팀으로 전환 가능:
`TeamCreate`로 4개 조사 에이전트 팀 구성 → `tech-trend`가 키워드 확정 즉시 `SendMessage`로 공유 → 나머지가 자체 조율.
기본은 서브에이전트 팬아웃(오버헤드 낮음).

## 테스트 시나리오
- **공고 미정 흐름**: "우리 분야 낼 만한 공고 있나" → Phase 0.5 rfp-scout(별도 플러그인) → 프로파일 생성 → 포털 탐색 → 후보 7건·추천 3건 보고 → 사용자 선택 → 그 URL·첨부로 Phase 1 재개.
- **탐색만**: "이번 주 공고 훑어줘" → Phase 0.5만 수행 → `00_rfp_candidates.md` 보고 후 종료(계획서 작성 자동 진행 금지).
- **정상 흐름**: 공고문 PDF 입력 → (Phase 0.5 건너뜀) → RFP 1개 자동특정 → 과제명 확정(사용자 승인) → 4개 조사 병렬 완료 → 그림+HWPX 조립 → 평가위원 PASS → 최종 계획서 산출.
- **에러 흐름 1 (RFP 다수)**: 공고에 RFP 3개 → announcement-analyst가 NEEDS_USER_INPUT → 사용자 선택 대기 → 선택 후 재개.
- **에러 흐름 2 (검수 실패)**: 위원단 최저점 82(근거정합성 위원이 무근거 수치 지적) → hwpx-writer가 해당 섹션 보완 → 재평가. 전원 95+까지 반복, 4회 후에도 미달·정체면 잔여 리스크 명시 후 종료.
- **부분 재실행**: "특허조사만 다시" → Phase 0에서 부분 재실행 판정 → patent-researcher만 재호출 → `14_patent.md` 갱신 → hwpx-writer에 반영 필요 여부 안내.
