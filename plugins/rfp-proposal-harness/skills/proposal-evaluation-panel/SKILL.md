# 평가위원단 오케스트레이터 (95점 게이트 고도화 루프)

연구개발계획서를 **6개 독립 렌즈**로 채점하고, **전원 95점 이상**이 될 때까지
`hwpx-writer`(개정) ↔ 위원단(재평가)을 반복해 고도화한다.

> 공통 루브릭·감점 앵커: `references/rnd-evaluation-rubric.md`
> 실행 모드: 하이브리드 — 위원 채점은 병렬 팬아웃, 위원장 종합은 배리어, 개정은 순차.
> 모든 `Agent` 호출은 `model: "opus"`.

## 위원단 (6인)
| # | 에이전트 | 산출 | 축 |
|---|---------|------|----|
| 1 | proposal-evaluator (위원장) | `49_panel_verdict.md` | 부합성 + 종합·판정 |
| 2 | technical-merit-evaluator | `41_review_technical.md` | 기술성 |
| 3 | feasibility-evaluator | `42_review_feasibility.md` | 실현가능성 |
| 4 | impact-evaluator | `43_review_impact.md` | 사업화·파급 |
| 5 | evidence-integrity-verifier | `44_review_evidence.md` | 근거·정합성(게이트) |
| 6 | compliance-formatting-evaluator | `45_review_compliance.md` | 형식·규정 |

## 워크플로우

### Phase 0: 사전 확인
- `_workspace/30_proposal.*`(계획서)와 조사파일(`00~14`, `01_template_rules.md`)이 있는지 확인. 없으면 상위 오케스트레이터(작성 단계)를 먼저 요청.
- 반복 상한 `MAX_ITER = 4`, 목표 `TARGET = 95`.

### Phase 0.3: ★ 재현 문서 모드 선언 (해당 시)
실제 컨소시엄·기업 실적·확약서가 **없는 재현·연습 과제**는 **시작 시 「재현 모드」를 선언**하고,
그로 인한 감점(기관 실명·기업 실적 정량치·수요기업 확약서·양산 캐파·CAPEX/BEP)을 **축별로 사전 고지**한다.
위원은 이를 **매 라운드 재발견하지 않고 상수로 계상**한다.
> 실측: 이 고지가 없어 약 −5.0점의 「재현 문서라 못 채우는 항목」이 **8라운드 내내 재발견**되며
> 지시·논의를 소모했다. 실제 신청 시에는 자동 소멸하는 감점이다.

### Phase 0.5: ★★ 종료 조건 도달 가능성 사전 점검 (R1 종료 직후 — 생략 금지)
**R1 채점이 끝나면 즉시** 각 축의 **「회수 불가 감점 합」**을 산출해 **산술 천장**을 확정한다.

```
축별 천장 = 100 − Σ(회수 불가 감점)
  회수 불가 = 재현 문서의 원리적 한계 · 문서 외부 요인(분량 정책·기관 확정 등) · 【C】 항목
천장 < TARGET 인 축이 하나라도 있으면 → 게이트는 원리적으로 도달 불가
```
**천장 < TARGET이면 즉시 사용자에게 상신**하고 종료 조건을 조정한다. 위원장 직권으로 바꾸지 않는다.

> ★ **이 하네스에서 가장 비쌌던 비용은 결함이 아니라 「달성 불가능한 종료 조건을 7라운드 동안 추격한 것」**이다.
> 형식 축 천장이 91.85(분량 −6.65 + 기관 실명 −1.50)여서 「6축 전원 95」는 처음부터 불가능했는데,
> 이를 **7라운드째에야** 발견했다. R1에서 천장을 계산했다면 R2에 알 수 있었다.

**대체 종료 조건 예시(실제 채택안)** — 사용자 승인 필수:
① 천장이 게이트 미만인 축을 **제외한 나머지 축 ≥ TARGET**
② 그 축은 **「회수 불가 감점 제외 소계」 ≥ TARGET** (해당 위원이 산정 규칙을 명문화할 것)
③ **【A】 잔여 0**  ④ **규율 H·I·J 전항 통과 + validate VALID**

### Phase 1: 병렬 채점 (팬아웃)
위원 2~6을 **병렬 실행**(`Agent(..., model:"opus", run_in_background:true)`):
- technical / feasibility / impact / evidence / compliance → 각자 `4x_review_*.md` 생성.
각 결과 첫 줄 `## SCORE: NN/100 STATUS:` 를 수집한다.

### Phase 2: 위원장 종합 (배리어)
5개 위원 결과가 모이면 `proposal-evaluator` 실행 → `49_panel_verdict.md`.
- 6개 점수표 + 최저점 계산. 판정 규칙:
  - **전원 ≥ 95 AND evidence STATUS=PASS → FINAL: PASS** → Phase 4.
  - 아니면 **FINAL: REVISE** → Phase 3.

### Phase 3: 고도화 개정 (순차 루프)
1. `49_panel_verdict.md`의 **섹션별 통합 수정지시**를 `hwpx-writer`에 전달 → 지적 섹션만 개정 → `30_proposal.*` 갱신.
2. 개정 이력을 `_workspace/48_revision_log.md`에 append (회차·최저점·주요 수정).
3. **Phase 1로 돌아가 재평가.** 단, 재평가는 이전 REVISE였던 위원 + evidence(게이트)를 우선 재실행하고, 나머지는 관련 섹션이 바뀌었으면 재실행.
4. `MAX_ITER` 도달 시 종료하고 잔여 미달 항목을 "잔여 리스크"로 보고(무리한 통과 금지).

### Phase 4: 최종 보고
- 최종 점수표(6축)와 수렴 곡선(회차별 최저점, `48_revision_log.md` 기반)을 사용자에게 보고.
- 최종 계획서 경로 + `49_panel_verdict.md` 요약 제시.

## 95+ 수렴을 돕는 규칙 (고도화 핵심)
- 위원은 점수만 주지 말고 **Gap-to-95(섹션 단위 실행지시)**를 반드시 남긴다 → 개정이 표적화된다.
- 위원장은 지시를 **섹션별로 병합·우선순위화** → writer가 한 회차에 다중 지적을 처리.
- **근거(evidence) 게이트**: 다른 점수가 높아도 근거 결함이 있으면 PASS 불가 → 숫자만 높은 껍데기 방지.
- 개정은 **지적 섹션만** 수정(전면 재작성 금지) → 이미 95인 축의 회귀(regression) 방지.
- **규율 L(【A】 무손실 이관)** — 위원장이 【A】를 취사선택하지 않는다. 상세는 `proposal-evaluation` 스킬.
  실측상 **효과가 점수로 측정된 유일한 규율**이다(근거 축 94.0 → 100.0).
- **위원은 배점 회수표를 미리 공시한다** — "이 항목 이행 시 +N.N"을 판정문에 적어두면,
  다음 라운드 점수가 **목표가 아니라 산출값**이 된다. 사후 정당화를 막는다.

## ★ J-6 「측정 매체」 필수 서식 (전 위원 공통)
모든 게이트·체크 항목에 **「측정 매체」 열**(md / hwpx / hwpx원시 / svg / 자산 / 조사파일 / COM)을 부착한다.
- **md 단독 측정 항목은 「통과」를 발급할 수 없다** → 「미검증」으로 표기한다.
- 각 판정문에 **「본 위원이 직접 측정할 수 없는 항목」 절**을 두고 위원장에게 고지한다.

> 실측 근거 ⓐ 「평가방법 8행 존재」가 md에서는 참이고 산출물에서는 거짓이었다(표가 2개로 분할).
> ⓑ 형식 위원 감점의 **80.6%가 PageCount**인데 이는 위원이 측정할 수 없는 제3자 보고값이다 —
> 「PASS」로 위장하지 말고 "COM 보고값 수용"으로 표기해야 한다.

## 반복 개정이 신규 결함을 낳는다 — 라운드 설계
실측 신규 결함 주입량: v2 9건 · v3 4~6건 · v4 4건 · v5 3~5건 · v7 **21.15점**.
- 편집 25건·조사 14건·압축 3회를 **한 회차에 몰아 넣으면** 이행률이 높아도 그만큼 결함이 들어온다.
- 따라서 **개정 라운드 뒤에는 「검증 전용 라운드」**(신규 서술 추가 금지, 회귀·매체 정합·필수기재만 확인)를 배치한다.
- 검증 전용 라운드는 비용이 약 60%이고, 이 하네스에서 **PASS를 확정한 것이 바로 이 라운드**였다.

## 데이터 전달
- 파일 기반. 리뷰 `_workspace/4x_review_*.md`, 종합 `49_panel_verdict.md`, 이력 `48_revision_log.md`.
- 각 파일 첫 줄 STATUS/SCORE 라인으로 루프 제어.

## 에러 핸들링
- 위원 1명 실패 → 1회 재시도, 재실패 시 해당 축 "미평가" + REVISE 유지(누락으로 PASS 금지).
- writer 개정 실패 → 해당 회차 스킵하고 잔여 리스크에 명시.
- 무한루프 방지: 두 회차 연속 최저점 개선이 +1 미만이면 "정체"로 판단, 사용자에게 근본적 보완(추가 조사·목표 재설정) 필요를 보고.

## 테스트 시나리오
- **정상**: 초기 최저 78 → 개정 3회 → 6축 전원 ≥95 → PASS 보고.
- **근거 게이트**: 기술성 97이지만 evidence 82(허위 특허번호) → REVISE → 특허 교체 → evidence 96 → PASS.
- **정체**: 최저점이 88→89→89 정체 → 정체 판정 → 시장조사 심화 등 근본 보완 제안 후 중단.
- **부분 재평가**: "형식만 다시 봐줘" → compliance-formatting-evaluator만 재실행 → 위원장 종합 갱신.
