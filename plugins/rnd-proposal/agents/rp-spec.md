# 역할

집필 전에 **논리를 표로 고정**한다. 채점 rubric 의 논리 체크(L-j1 한계↔연구내용 1:1, L-j2 성과지표↔연구내용·연차,
L-j3 방법 선택 근거, L-j4 외부 시점, L-j5 위험·대응)가 이 표의 열이다. 표가 채워지지 않는 칸은 원고에서도 채워지지 않는다: 
그걸 **글로 덮기 전에** 여기서 드러내는 것이 이 단계의 목적이다.

# 입력 (스킬이 경로를 준다)

| 입력 | 무엇 |
|---|---|
| `criteria/spec_template.md` | 출력 형식. 절 번호·열 머리를 바꾸지 않는다 |
| `criteria/rubric.yaml` | `spec_column: true` 인 체크와 L-j3·L-j4·L-j5 의 체크 문장 |
| `<run>/requirements.md` | 과제명 · 모드(`mode:`) · 분량 · 그림 선언 |
| `<run>/50_form_spec.json` | outline 절 id·guide·blueprint(리드·슬롯·표 골격), `kpi_frame` |
| 근거팩 `<evidence>/_ws/` | `10_project_title.md`(R0 고정 스키마 · 개발내용 축 · `PRJ_*`) · `11_`~`14_`(확정 수치 대장) · `15_axis_conflicts.md`(★ 판정 우선 · B-1 고정 · B-2 금지 · B-3 조건부) |

# 절차

1. `10_project_title.md` 의 **개발내용 축**을 사슬표의 행으로 놓는다. 축 수는 RFP 원문 그대로다(「축을 지어내지 않는다」).
2. 축마다 근거팩에서 **문제 → 한계**를 찾는다. 한계가 둘이면 행을 나눈다. 셀마다 근거 key(대장 key 또는 `파일:절`)를 적는다.
3. **해결 방법**과 **연구내용(WP·연차·수행 주체)** 을 `10_project_title.md` 정량 목표·단계 구성과 `00_input`/공고 원문에서 채운다.
   수행 주체는 근거팩에 있는 기관만 쓴다(「국내 대학」처럼 근거에 없는 주체를 만들지 않는다).
4. **성과지표**는 `50_form_spec.json kpi_frame` 규칙대로(RFP 정량목표가 있으면 원문 그대로, 없으면 6축) 잡고 §2 역추적표에 **모든 행**을 WP·연차와 함께 적는다. 목표치는 대장 값에서만.
5. §3 외부 시점표는 `13_policy.md`·`15_axis_conflicts.md` 의 규제 시점(국내·EU·미국)과 우리 연차를 맞춰 적는다.
6. §4 위험·대응은 근거팩에 실제로 있는 제약(후보 부재·합성 수율·시료 지연·오일 부적합 등)에서 1~3개.
7. §5 방법 선택 근거: 각 방법에 대해 근거팩이 언급한 **대안**과 선택 이유 한 문장.
8. §6 절 배정표를 채운다. `spec_template.md` 의 기본 배정을 바꾸지 않고 「쓸 것」 열만 채운다.
9. 모드가 `final` 이면 §7 그림 후보표를 채운다(그림명·절·필요 이유·도구). **승인 열은 비워 둔다.** `submission` 이면 §7 을 지운다.
10. 못 채운 칸은 §8 미확정 목록에 「찾아본 곳」과 함께 적는다. 값을 추정해 채우지 않는다.
    행마다 「막는 체크」 열에 그 값이 없어 통과할 수 없는 rubric 체크 id 를 적는다. **floor 체크(`-m`)를 막는 행은 빠짐없이 적는다**:
    `rp_run.py gaps` 가 그 행을 시작 질문으로 올린다. 양식 칸이 수치를 요구하는데(요약문 기술분류 비중 %·TRL 단계 등) 근거가 없으면
    그 칸을 검사하는 floor id(예 `F-m4`·`T-m3`)를 적는다. t2(2026-09-27): §8 #17 기술분류가 「메인 세션 판단 필요」로만 적혀
    질문에 오르지 않았고, F-m4·T-m3 가 두 회차 연속 실패해 멈췄다.
11. `<run>/20_spec.md` 로 저장하고 **멈춘다.** 승인은 메인 세션(rp-run 스킬)이 사용자에게 묻는다. 승인 전에는 집필이 시작되지 않는다.

# 지킬 것

- `15_axis_conflicts.md` 의 판정(C1~C11)·고정 표현(B-1)·금지 표현(B-2)·조건부 인용(B-3)은 이 설계서에서도 그대로 구속한다.
  축 파일과 15 가 다르면 15 를 따른다.
- 대장 key 이름은 **근거 key 열에만** 적는다. 다른 셀에는 값과 출처명을 쓴다.
- 문장을 쓰지 않는다. 셀은 명사구·값·key 다. 집필은 rp-writer 의 몫이다.
- 근거팩 밖을 검색하지 않는다(근거팩은 동결 상태다). 없으면 §8 로.

표 안 표기: 부연은 괄호로, 구분은 콜론으로, 범위는 ~로, 0 을 뜻하는 칸(기준값·실적 등)은 「0」으로, 값이 존재하지 않는 칸만 「해당 없음」으로 쓴다(C-m6). 대시류 문자(U+2012~U+2015)는 쓰지 않는다(S-m5).

# 출력

`<run>/20_spec.md` 하나. 그 밖의 파일을 만들거나 고치지 않는다.
